This plan maps the Year 2 Semester 1 modules at **University of Reading (2026/27)** and
turns their required topics into a week-by-week study timetable for the Autumn term.
It sits as a standalone document between the References and Timetable sections of the
project so that `README.md` and `NOTES.md` remain untouched.

## Weekly Study Template

Anchored on the owner's confirmed **Semester 1** contact hours. Wednesday and
Friday are the only full free days, so they carry the deep work; the four
contact days are maintenance-only, and Tuesday is deliberately light because
it is a late finish.

| Day | Status | Session |
| --- | --- | --- |
| Monday | Study (late) | University 11:00 AM - 4:00 PM, home by 6:00 PM -> study 6:30 PM - 9:00 PM |
| Tuesday | Rest / optional light | University 2:00 PM - 6:00 PM, home by 8:00 PM -> **rest by default** (tired); optional 20-minute review only |
| Wednesday | Study (deep) | Free -> 9:00 AM - 12:00 PM and 1:30 PM - 4:30 PM (6 hrs, 2 blocks) |
| Thursday | Study (late) | University 9:00 AM - 4:00 PM, home by 6:00 PM -> study 6:30 PM - 9:00 PM |
| Friday | Study (deep + career sprint) | Free -> 9:00 AM - 12:00 PM and 1:30 PM - 4:30 PM (6 hrs, 2 blocks) |
| Saturday | Study (light + review) | 7:00 PM - 9:00 PM (2 hrs, one block) |
| Sunday | Study (light + review) | 7:00 PM - 9:00 PM (2 hrs, one block) |

**Term-time total: ~21 hrs/week** (Wed 6 + Fri 6 + Sat 2 + Sun 2 + Mon 2.5 +
Thu 2.5). Note this is *scheduled availability*, not a target - the previous
template nominally reached 28 hrs by stacking a 12-hour Wednesday, which was
neither realistic nor sustainable. The real gain here is shape, not size: the
work is front-loaded into the two genuinely free days instead of spread across
every evening.

> **Tuesday is the load-bearing rest day.** Two of five contact days already
> end with a long commute; a third evening of study after a 2:00 PM - 6:00 PM
> day is where the streak breaks. Do not schedule assessment work for
> Tuesday. If Tuesday has to be used (deadline week), keep it to a 20-minute
> retrieval check, not new material.

## Modules and Required Topics

### CS2DA - Data Structures and Algorithms

20 credits, Semester 1. 50% open exam + 50% technical report (7 pages, due Week 11).
Convenor: Dr Martin Lester.

| Topic | Details |
| --- | --- |
| Data Structures | Trees (binary trees, BST, traversals), heaps, graphs (representations, BFS, DFS) |
| Divide and Conquer | General method, analysis, examples: sorting, convex hull, matrix multiplication |
| Greedy Method | General method, analysis, examples: shortest paths, spanning trees |
| Dynamic Programming | General method, analysis, travelling salesperson, transitive closure |

### CS2PP - Programming in Python

20 credits, Semester 1 (28 September to 29 January). 40% set exercises (due Week 7)

- 60% group application project (demonstrated in January assessment week).
Convenor: Dr Todd Jones.

| Topic | Details |

| Paradigms | Functional programming, object-oriented programming |
| Environment | Python environments, packages, and modules |
| Data Manipulation | I/O, NumPy, Pandas, scikit-learn |
| Specialised Applications | Image manipulation, GUI programming, web programming |

### CS2SE - Software Engineering & Professional Development

20 credits, Semester 1. Group technical report Stage 1 (50%) and Stage 2 (50%).

| Topic | Details |

| Architecture | Software systems architecture, frameworks, and standards |
| SE Paradigms | Requirements engineering, iterative development, design, testing, deployment, versioning |
| Management | Evolution, systems thinking, scalability, performance, project planning, team management |
| Risk and Ethics | Risk analysis, security, ethical and professional responsibilities |
